# 06 · 屏幕绘图、坐标与「黑屏陷阱」

本章是**本仓库最该先读的一章**：三个固件曾经全部真机黑屏，根因就在这一页。

---

## 6.1 坐标系复习

```
(0,0) ──────────→ x：0 ~ 159
  │
  │    160 × 120
  ↓
 y：0 ~ 119（往下变大！）
```

- 逻辑分辨率固定 160×120，引擎负责放大到物理屏。
- **往下 y 变大**，所以「向上飞」的速度写负数。
- 精灵的 `x / y` 是**中心点**；`fillRect / print` 的 `x / y` 是**左上角**。

---

## 6.2 直接画屏的五个 API

| 作用 | TypeScript | 静态 Python |
| --- | --- | --- |
| 全屏填一个颜色 | `screen.fill(c)` | `screen.fill(c)` |
| 画实心矩形 | `screen.fillRect(x, y, w, h, c)` | `screen.fill_rect(x, y, w, h, c)` |
| 画空心矩形 | `screen.drawRect(x, y, w, h, c)` | `screen.draw_rect(x, y, w, h, c)` |
| 画线 | `screen.drawLine(x0,y0,x1,y1,c)` | `screen.draw_line(x0,y0,x1,y1,c)` |
| 画一个像素 | `screen.setPixel(x, y, c)` | `screen.set_pixel(x, y, c)` |
| 左对齐文字 | `screen.print(s, x, y, c)` | `screen.print(s, x, y, c)` |
| 居中文字 | `screen.printCenter(s, y, c)` | `screen.print_center(s, y, c)` |

`c` 是 **0~15 的调色板编号**。文字默认字高约 8 像素，一行大约能放 26 个英文字符。

```ts
game.onShade(function () {
    screen.fill(15)                          // 黑底
    screen.fillRect(10, 20, 40, 16, 8)       // 蓝色方块
    screen.drawRect(10, 20, 40, 16, 1)       // 白边框
    screen.printCenter("HELLO", 50, 5)       // 黄色居中
    screen.print("X:10", 12, 22, 1)          // 白字
})
```

`scene.setBackgroundColor(c)` 设置的是**引擎背景色**（每帧自动清屏用），和 `screen.fill()` 不是一回事。

## 6.3 ⚠️ 黑屏陷阱：绘制必须放 `onShade`

引擎每一帧的固定顺序：

```
① game.onUpdate(...)          逻辑：算坐标、碰撞、分数
② scene.render()
     └─ background.draw() → screen.fill(背景色)   ← 全屏擦除！
③ 画精灵 / HUD
④ game.onPaint(...) → game.onShade(...)          ← 画你自己的界面
⑤ 送到屏幕
```

**结论**：把 `screen.fill()` / `printCenter()` 写在 `game.onUpdate` / `game.on_update` 里，画完立刻被第 ② 步擦掉。程序其实一直在跑，屏幕却是纯黑 —— 极像「刷机失败」，其实只是代码放错了回调。

| 回调 | 放什么 |
| --- | --- |
| `game.onUpdate` / `on_update` | **只算不画**：重力、移动、碰撞、状态 |
| `game.onShade` / `on_shade` | **只画不算**：`screen.fill` / `fillRect` / `print` |

```python
# ✅ 正确
def update():
    global x
    x = x + 1

def draw():
    screen.fill(15)
    screen.fill_rect(x, 60, 8, 8, 5)

game.on_update(update)
game.on_shade(draw)      # ← 关键

# ❌ 错误：会全黑
# game.on_update(draw)
```

> 本仓库用最小探针实测过：`onUpdate` 画的红色半屏被擦成背景色，`onShade` 画的绿色半屏保留；`04-game-collection` 修复前画布非黑像素为 **0**，与真机黑屏现象完全一致。这就是本仓库三个固件返工的原因。
> 想自己复现：刷入 `projects/_render-probe/`（6 行代码，左半屏红写在 `onUpdate`、右半屏绿写在 `onShade`），屏幕上只会看到绿色那一半。

**标准精灵系统不会遇到这个问题**（引擎负责画精灵），所以 `01/02/03` 用 `sprites.create` 的项目不受影响。只有「直接画屏」的项目要注意。

## 6.4 两种写法：精灵系统 vs 立即模式

| | 精灵系统（01/02/03） | 立即模式（05/06） |
| --- | --- | --- |
| 怎么画 | `sprites.create(...)`，引擎自动画 | 每帧 `screen.fillRect(...)` 自己画 |
| 碰撞 | `sprites.onOverlap(...)` 自动判 | 自己写 `hit()` 矩形相交 |
| 占用 | 图片资源 + 精灵对象较多 | 几乎只占代码，Flash 更省 |
| 适合 | 小游戏、教学、快速出效果 | 大合集、菜单、表格类界面 |

`06-legend-collection` 四个大游戏塞进一个 UF2 只用了 343 KiB，靠的就是立即模式。

## 6.5 16 色调色板

| 编号 | 颜色 | 编号 | 颜色 |
| --- | --- | --- | --- |
| 0 | 透明 | 8 | 蓝 |
| 1 | 白 | 9 | 青 |
| 2 | 红 | 10 | 紫 |
| 3 | 粉 | 11 | 浅蓝 / 灰蓝 |
| 4 | 橙 | 12 | 棕 |
| 5 | 黄 | 13 | 深红 |
| 6 | 青绿 | 14 | 深蓝 |
| 7 | 绿 | 15 | 黑 |

**注意**：`15` 是黑，`1` 是白；像素画里的 `f` / `.` 是透明。
黑底白字用 `screen.fill(15)` + `print(..., 1)`；高亮项常把颜色号从 `1` 换成 `5`（黄）。

## 6.6 常见界面元素怎么写

### 顶部 HUD（写在 `onShade` 里）

```ts
function hud(title: string, score: number, extra: string) {
    screen.fillRect(0, 0, 160, 10, 15)          // 黑条
    screen.print(title, 2, 1, 7)
    screen.print("SC:" + score, 76, 1, 1)
    screen.print(extra, 122, 1, 5)
}
```

### 菜单（数组 + 循环 + 高亮）

```ts
const names = ["SNAKE", "JUMP", "SHOOT", "TANKS"]
game.onShade(function () {
    screen.fill(15)
    screen.printCenter("RETRO 4-IN-1", 8, 5)
    for (let i = 0; i < 4; i++) {
        const c = cursor === i + 1 ? 5 : 1      // 选中变黄
        screen.printCenter((i + 1) + ". " + names[i], 30 + i * 18, c)
    }
})
```

### 进度条（长按 B 返回菜单的提示）

```ts
const w = Math.min(160, Math.floor(progress * 160 / 1200))
screen.fillRect(0, 118, w, 2, 5)
```

### 弹窗

```ts
screen.fillRect(6, 32, 148, 56, 9)
screen.fillRect(8, 34, 144, 52, 15)
screen.printCenter("GAME OVER", 40, 5)
```

## 6.7 每帧都要重画（没有「保留上一帧」这回事）

`onShade` 每帧被调用一次，**上帧的像素不会自动留着**。所以：

1. 第一句通常是 `screen.fill(背景色)` 清屏；
2. 然后把这一帧要显示的**所有**东西都画一遍；
3. 不要把「只画一次」的东西放在 `onShade` 外面（会被清掉）。

想画「一直在动」的星空，就把星点坐标存成数组，每帧根据 `frame` 重新算一遍画一遍（`06-legend-collection/main.ts` 的菜单就是这么做的）。

## 6.8 中文与字体

默认字库**只有 ASCII**：中文、emoji 会显示成方块或空白。
所以本仓库所有界面文字都是英文。真要中文，得自己画点阵字库（每个字 12×12 约 18 字节，常用 100 字就 1.8 KiB，还要写渲染函数）—— 入门阶段不值得。

## 6.9 本章最小可运行例子：会反弹的小球

**TypeScript**

```ts
let x = 20, y = 40, vx = 2, vy = 1
scene.setBackgroundColor(15)
game.onUpdate(function () {
    x += vx; y += vy
    if (x < 0 || x > 152) vx = -vx
    if (y < 12 || y > 112) vy = -vy
})
game.onShade(function () {
    screen.fill(15)
    screen.printCenter("BOUNCE", 2, 5)
    screen.fillRect(x, y, 8, 8, 5)
})
```

**静态 Python**

```python
x = 20
y = 40
vx = 2
vy = 1
scene.set_background_color(15)

def update():
    global x, y, vx, vy
    x = x + vx
    y = y + vy
    if x < 0 or x > 152:
        vx = -vx
    if y < 12 or y > 112:
        vy = -vy

def draw():
    screen.fill(15)
    screen.print_center("BOUNCE", 2, 5)
    screen.fill_rect(x, y, 8, 8, 5)

game.on_update(update)
game.on_shade(draw)
```

**课堂任务**：把 `on_shade(draw)` 改成 `on_update(draw)`，刷进去看黑屏，再改回来 —— 孩子一辈子都记得这个坑。
