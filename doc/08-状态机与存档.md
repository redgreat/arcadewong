# 08 · 状态机、存档与「一个 UF2 装多个游戏」

这一章回答那个最常见的问题：**「机器一次只能刷一个游戏，能不能装好多游戏？」** 能 —— 但方式和你以为的不一样。

---

## 8.1 先搞清楚 UF2 烧录是什么

拖 `.uf2` 进 `ARCADE-F4` 盘，是**把整块应用区整体覆盖成一个程序**，不是往文件夹里复制文件。

- ❌ 拖第二个 UF2 进去 → 第一个被覆盖。
- ✅ 在**一个程序里**写多个游戏的分支 → 想装几个装几个。

这台机器**没有 SD 卡、没有文件系统**，所以「像手机一样存一堆 ROM、开机选一个加载」做不到。
但 Flash 里有一小块可以存几个数字：`settings`。于是有了下面这个巧妙做法。

---

## 8.2 `settings`：只能存「一个数字」

```ts
settings.writeNumber("g", 2)      // 存一个数字，键名 "g"
let n = settings.readNumber("g")  // 读出来；没存过返回 0
```

```python
settings.write_number("g", 2)
n = settings.read_number("g")
```

| 用途 | 例子 |
| --- | --- |
| 记住用户选了第几个游戏 | `settings.writeNumber("lg", 3)` |
| 存最高分 | `settings.writeNumber("s_best", score)` |
| 存设置项 | 音量、难度、上次玩的角色 |

⚠️ **读写键名必须一致**（`readNumber("g")` 配 `writeNumber("h", ...)` 永远读不到）。
⚠️ 只能存数字，刷新 / 重新烧 UF2 后数据可能保留也可能被清，别当数据库用。

---

## 8.3 `game.reset()`：软重启

```ts
game.reset()
```

程序**从第一行重新执行**：所有精灵、事件回调、分数、局部变量全部清空。
相当于「换一局桌游，把棋子全收回去」，比自己写一堆清理代码干净得多。

---

## 8.4 组合起来：菜单 + 多游戏

```ts
const MENU = 0
let selected = settings.readNumber("g") || 0
if (selected !== 0) settings.writeNumber("g", 0)   // ★ 关键：读完立刻清零
let cursor = 1

// 任何时候按 B 回菜单
controller.B.onEvent(ControllerButtonEvent.Pressed, function () {
    settings.writeNumber("g", MENU)
    game.reset()
})

if (selected === MENU) {
    // 菜单分支：↑↓ 改 cursor，A 写入选择并重启
    controller.A.onEvent(ControllerButtonEvent.Pressed, function () {
        settings.writeNumber("g", cursor)
        game.reset()
    })
    game.onShade(function () { /* 画菜单 */ })
} else if (selected === 1) {
    startCatch()
} else if (selected === 2) {
    startFlappy()
} else {
    startShooter()
}
```

### ★ 为什么「读完立刻清零」不能省

如果不清零，下次**冷开机**（拔线重插、按复位）`settings` 里还是上次的值，会直接跳进那个游戏，永远回不了菜单。
「读完立刻写 0」保证：**只有本次软重启**才直达游戏。

### 执行流程（画给孩子看）

```
开机 / 复位
   ↓
读 settings["g"]  →  是 0 吗？
   ├─ 是 → 显示菜单 → 按 A → 写 settings["g"]=选择的编号 → game.reset() ┐
   └─ 否 → 立刻把 settings["g"] 清 0 → 启动第 N 个游戏                  │
                                                                          │
        ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ← ┘
                        （按 B：写 0 → game.reset()）
```

这就是**状态机**的雏形，比讲术语有效得多。

## 8.5 为什么多个游戏不会把内存撑爆

| 资源 | 情况 |
| --- | --- |
| **Flash（448 KiB 应用区）** | 装所有游戏的**代码**，是累加的 |
| **SRAM（96 KiB）** | 只装**当前正在跑的那一个**游戏的数据 |

因为 `game.reset()` 之后**只有一个分支被执行**，另外几个游戏的代码静静躺在 Flash 里，不占运行内存。

`06-legend-collection` 实测：四个大游戏 + 菜单共 **344.2 KiB / 448 KiB（76.8%）**，还剩约 104 KiB。
逐项体积：空壳 280.5 KiB，贪吃蛇 +8.0、闯关 +18.2、枪战 +19.0、坦克 +19.2 KiB。

**加游戏时的正确姿势**：一次只加一个，每加一个就编译一次看 `binary.uf2` 体积，别一口气写完再发现超了。

## 8.6 状态机的另一种形态：`state` 变量

不用重启也能切换界面 —— 用一个数字记录「现在是第几步」：

```python
state = 0   # 0 待开始 / 1 随机等待 / 2 变绿计时 / 3 显示结果

def press():
    global state
    if state == 0:
        state = 1
    elif state == 2:
        state = 3
    elif state == 3:
        state = 0
```

`05-toolbox` 的反应速度测试就是这么写的。**同一个 A 键，在不同 state 下含义完全不同**。
类比红绿灯：画 4 个圈写 0/1/2/3，再用箭头标「按 A 从哪个圈走到哪个圈」，孩子一看就懂。

### 两种方案怎么选

| 方案 | 优点 | 缺点 | 用在 |
| --- | --- | --- | --- |
| `settings + game.reset()` | 状态彻底清干净，游戏之间零干扰 | 重启有短暂黑屏 | `04 / 05 / 06` 的菜单 |
| `state` 变量 | 无缝切换、不黑屏 | 要自己清理上一状态的变量 | 单个应用内的多界面 |

## 8.7 按键不够用：长按 B 返回菜单

`06-legend-collection` 里 B 在游戏内还要用来射击/冲刺，短按不能抢。解法：

```ts
let bHold = 0
game.onUpdate(function () {
    if (controller.B.isPressed()) {                 // 持续检测，不是 onEvent
        if (bHold === 0) bHold = control.millis()
        const held = control.millis() - bHold
        if (held >= 1200) toMenu()                  // 长按 1.2 秒
        // 同时在 onShade 里画一条黄色进度条，把等待可视化
    } else {
        bHold = 0
    }
})
```

`isPressed()`（是否正按着）和 `onEvent(Pressed)`（按下的那一瞬间）是两回事，见 [第 4 章](04-函数与事件.md)。

## 8.8 Python 版完整菜单骨架

```python
MENU = 0
selected = settings.read_number("lg")
if selected != 0:
    settings.write_number("lg", 0)
cursor = 1

def to_menu():
    settings.write_number("lg", MENU)
    game.reset()

def start_game(n):
    settings.write_number("lg", n)
    game.reset()

def menu_up():
    global cursor
    if cursor == 1:
        cursor = 4
    else:
        cursor = cursor - 1

def menu_play():
    start_game(cursor)          # 只读 cursor，不需要 global

def draw_menu():
    screen.fill(15)
    screen.print_center("RETRO ARCADE", 8, 5)
    for i in range(4):
        screen.print_center(str(i + 1) + " GAME", 30 + i * 18,
                            5 if cursor == i + 1 else 1)

controller.B.on_event(ControllerButtonEvent.PRESSED, to_menu)

if selected == MENU:
    controller.up.on_event(ControllerButtonEvent.PRESSED, menu_up)
    controller.A.on_event(ControllerButtonEvent.PRESSED, menu_play)
    game.on_shade(draw_menu)
elif selected == 1:
    snake_start()
# ... 其余分支
```

注意 `menu_up()` 要 `global cursor`（赋值），`menu_play()` 不用（只读）。

## 8.9 常见坑

| 现象 | 原因 |
| --- | --- |
| 开机直接进游戏，回不了菜单 | 忘了「读完立刻清零」 |
| 菜单选了没反应 | 读写 `settings` 的键名不一致 |
| 多个游戏同时跑、屏幕乱套 | 把几段代码平铺在顶层，没放进 `if/else` 分支 |
| 回菜单时游戏音效还在响 | 没用 `game.reset()`，自己清理不干净 |
| B 键在游戏里失效 | 全局 B 事件抢了；改用长按方案 |
| 加游戏后编译失败 / 刷不进 | Flash 超 448 KiB；每加一个就量一次体积 |

---

## 8.10 延伸：为什么「GB 模拟器 + 加载好多游戏」做不到

不是「软件不够努力」，是硬件没有存放 ROM 的地方：

- 96 KiB SRAM：一帧 160×144 的 16 位色缓冲就要 46 KiB，直接爆；
- 无 SD 卡 / 无文件系统，32 KiB~数 MiB 的 ROM 无处可放；
- `ARCADE-F4` 是 bootloader 虚拟出来的**伪 U 盘**，不是真存储；
- MakeCode 静态 TS/Python 没有指针，写 CPU 解释器也不现实。

完整逐条分析见 [`硬件介绍.md`](硬件介绍.md)。**可行的替代就是本章的多游戏合集**。
